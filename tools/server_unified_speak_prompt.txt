[AGYSTACK TASK SPECIFICATION: CONTROLLER_GUIDED_SAY_V1 UNIFIED SPEAK VALIDATION FIX]

OBJECTIVE:
Allow `CONTROLLER_GUIDED_SAY_V1` responses to be properly validated and committed in `duplex_kernel/server.py`, preventing completed SPEAK responses from being erroneously rolled back and destroyed in the unified KV cache.

ROOT CAUSE:
In `duplex_kernel/server.py` line 8415-8426:
```python
unified_speak_valid = bool(
    not unified_kv_enabled
    or (
        action == ControlAction.SPEAK
        and isinstance(v2_metrics, dict)
        and v2_metrics.get("response_protocol") == AUDIO_RESPONSE_PROTOCOL_V2
        and v2_metrics.get("status") == "valid"
        and str(v2_metrics.get("response_action", "")).upper()
        == ControlAction.SPEAK.value
        and not result.get("_skip_history_commit")
    )
)
```
When running `--response-protocol controller_guided_say_v1`, `v2_metrics.get("response_protocol")` is `CONTROLLER_GUIDED_SAY_V1` ("controller_guided_say_v1") and `v2_metrics.get("status")` is `"controller_action_fixed"`.
Because line 8420 only checked `AUDIO_RESPONSE_PROTOCOL_V2` with status `"valid"`, `unified_speak_valid` evaluated to `False`.
This caused:
1. `assistant_completed` evaluated to `False`.
2. `archived_assistant` was not committed.
3. `unified_native_branch["history_committed"]` remained `False`.
4. When playback completed, the cache finalizer saw `history_committed == False` and rolled back the entire assistant response to turn start, erasing all generated KV tokens and leading to a desynchronization crash with `CONTROL6_CONTEXT_UNAVAILABLE` on subsequent listener ticks.

