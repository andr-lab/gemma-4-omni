Ecco la diagnosi root-cause, l'analisi di fedeltà architetturale e le patch esatte.

---

### (A) Causa Root del Dtype Mismatch (`mat1=Float, mat2=BFloat16`)

La causa risiede nella combinazione di **due anomalie** tra il setup di caricamento pesi e la costruzione manuale di `input_embeddings` in `extract_ht`:

1. **Il punto di rottura esatto**:
   In `modeling_qwen3_tts.py` (riga 773), all'interno di `Qwen3TTSTalkerAttention.forward`:
   ```python
   query_states = self.q_norm(self.q_proj(hidden_states).view(hidden_shape)).transpose(1, 2)
   ```
   Qui `self.q_proj` (layer 0 del talker) è un `nn.Linear(2048, 2048, bias=False)` i cui pesi sono in **`torch.bfloat16`** (`mat2`).
   L'input `hidden_states` (proveniente da `inputs_embeds`) entra invece come **`torch.float32`** (`mat1`). La chiamata interna `F.linear(hidden_states, self.q_proj.weight, None)` solleva immediatamente `RuntimeError: mat1 and mat2 must have the same dtype, but got Float and BFloat16`.

2. **Perché `inputs_embeds` era `Float`**:
   - In `fitnets_extract_cell2.py` (riga 119), `teacher = _M.Qwen3TTSForConditionalGeneration(_cfg).to(torch.bfloat16)` è stato eseguito **prima** di `load_state_dict(_sd)`. Successivamente (riga 129), `teacher = teacher.to("cuda")` sposta il device su CUDA ma **non** forza il cast ricorsivo di tutti i sotto-moduli a `bfloat16`.
   - In `extract_ht` (righe 205-212), la somma `input_embeddings = input_text_emb + input_codec_emb + Σ ci` accumula i tensori senza forzare esplicitamente `.to(talker.dtype)` e senza passare per la `text_projection`, esponendo il tensore a conversioni implicite di tipo prima del passaggio a `talker(inputs_embeds=...)`.

---

### (C) Verdetto Fedeltà `text_projection` (Analisi Critica)

**Verdetto: La `text_projection` è OBBLIGATORIA. Ometterla corrompe completamente i target $h_t$.**

- **Verifica Config**: in `cfg_talker.json`, `text_hidden_size: 2048` e `hidden_size: 2048`.
- **Verifica Modeling**: in `modeling_qwen3_tts.py` (righe 1575-1577 e 808-816):
  ```python
  self.text_projection = Qwen3TTSTalkerResizeMLP(
      config.text_hidden_size, config.text_hidden_size, config.hidden_size, config.hidden_act, bias=True
  )
  ```
  `ResizeMLP` **NON è un'identità** anche quando `text_hidden_size == hidden_size`:
  È un modulo MLP a 2 layer lineari con attivazione non-lineare **SiLU** (`linear_fc1` $\to$ SiLU $\to$ `linear_fc2`) con pesi e bias addestrati presenti in `model.safetensors` (`talker.text_projection.linear_fc1.weight`, ecc.).
- **Comportamento Ufficiale**: in tutto il modeling ufficiale (`generate`, `generate_icl_prompt`, `sft_12hz.py`), il canale testo passa SEMPRE attraverso la proiezione:
  $$\text{text\_emb} = \text{talker.text\_projection}(\text{talker.model.text\_embedding}(\text{input\_ids}_{text}))$$
  Sommare direttamente `talker.model.text_embedding` al canale codec senza `text_projection` inietta embedding non linearizzati nello spazio latente del talker, distruggendo la fedeltà dei layer intermedi e del layer 28 post-norm.

---

### (B) Patch Esatta di `fitnets_extract_cell2.py`

Ecco la patch che:
1. Forza `teacher` a `bfloat16` su `cuda` **dopo** il `load_state_dict`.
2. Integra la `text_projection` ufficiale su `input_text_emb`.
3. Cast esplicito di `input_embeddings` a `talker.dtype` (`torch.bfloat16`) prima del forward.

#### 2. Correzione Completa della Funzione `extract_ht` (righe ~196-222):
```python
    def extract_ht(item, n_real, text):
        audio_codes = item["audio_targets"][:n_real].long()  # (T_audio, 16)
        input_ids, codec_ids, text_mask, codec_emb_mask, codec_mask, attn = build_inputs(text, audio_codes)
        input_ids = input_ids.to("cuda")
        codec_ids = codec_ids.to("cuda")
        text_mask = text_mask.to("cuda")
        codec_emb_mask = codec_emb_mask.to("cuda")
        codec_mask = codec_mask.to("cuda")
        attn = attn.to("cuda")
        
        with torch.inference_mode():
            # 1. Proiezione non-lineare del canale testo (fedeltà 100% al forward ufficiale)
            raw_text_emb = talker.model.text_embedding(input_ids[:, :, 0])
            input_text_emb = talker.text_projection(raw_text_emb) * text_mask.unsqueeze(-1)
            
            # 2. Canale codec CB0
            input_codec_emb = talker.model.codec_embedding(input_ids[:, :, 1]) * codec_emb_mask.unsqueeze(-1)
            input_embeddings = input_text_emb + input_codec_emb
            
            # 3. Canali codec CB1..CB15
            for i in range(1, 16):
                ci = talker.code_predictor.get_input_embeddings()[i - 1](codec_ids[:, :, i])
                input_embeddings = input_embeddings + ci * codec_mask.unsqueeze(-1)
            
            # 4. Cast di sicurezza al dtype esatto del talker (bf16)
            input_embeddings = input_embeddings.to(dtype=talker.dtype)
            
            # 5. Forward talker
            outputs = talker(
                inputs_embeds=input_embeddings[:, :-1, :],
                attention_mask=attn[:, :-1],
                output_hidden_states=True,
                use_cache=False,
            )
            
            # 6. Estrazione h_t layer 28 post-norm
            hidden_states = outputs.hidden_states[0][-1]  # (1, t-1, 2048) bf16
            cm = codec_mask[:, :-1]
            ht_target = hidden_states[cm]  # (T_audio, 2048)
            
        return ht_target.float().cpu().numpy()
```

### (D) Raccomandazione Ottimizzazione `.dat` (Seconda Domanda)

#### Analisi Costi/Benefici su Kaggle (Budget GPU 30h/settimana)
1. **Stato attuale**: a ogni nuovo run, `convert_parquet_to_memmap` riesegue la conversione Parquet $\to$ `.dat` in `/kaggle/working` (peak RAM ~3.3GB per file, ~2-4 minuti persi di GPU time a vuoto).
2. **Opzione (b) Load Parquet diretto in RAM**: con 50h + MDC (13.6M frame), `pd.read_parquet` materializza ~7.3GB per file in memoria con picchi di oltre 18GB $\to$ crash OOM su istanze Kaggle standard.
3. **Opzione (a) Dataset Kaggle dedicato con i `.dat` (Raccomandazione Vincente)**:
   - I file `.dat` (`mel_user.dat`, `mel_agent.dat`, `codes.dat`) vengono caricati una tantum nel dataset di supporto Kaggle (ad es. `andrlab/gemma-4-omni-dat` o integrati in `andrlab/gemma-4-omni-module`).
   - Su Linux/Kaggle, `np.memmap(path, mode="r")` su `/kaggle/input/...` funziona in modo nativo e trasparente: il kernel mappa i byte dal filesystem squashfs/overlay **a zero copie di memoria** (RAM usage = 0 MB a startup, tempo di caricamento = **0.001 secondi**).
   - **Risparmio netto**: ~3-5 minuti di budget GPU per ogni singola sessione avviata.

#### Codice Modificato per `kaggle_pipeline.py` / `fitnets_extract_cell2.py`:

Sostituire la risoluzione dei path dei file `.dat` in `load_tokens_from_parquet` e `convert_parquet_to_memmap` per cercare prima nei dataset Kaggle allegati:

```python
def _find_dat_files(parquet_path: str) -> Tuple[Optional[str], Optional[str], Optional[str]]:
    """Cerca i .dat pre-convertiti: prima nei dataset di input Kaggle, poi in working/big_disk."""
    candidates = [
        os.environ.get("DAT_DIR", ""),
        "/kaggle/input/datasets/andrlab/gemma-4-omni-module/dat",
        "/kaggle/input/datasets/andrlab/gemma-4-omni-module",
        "/kaggle/input/gemma-4-omni-dat",
        os.path.dirname(parquet_path),
        big_disk_base(),
    ]
    for d in candidates:
        if not d or not os.path.isdir(d):
            continue
        u = os.path.join(d, "mel_user.dat")
        a = os.path.join(d, "mel_agent.dat")
        c = os.path.join(d, "codes.dat")
        if os.path.exists(u) and os.path.exists(a) and os.path.exists(c):
            return u, a, c
    return None, None, None
```

E in `load_tokens_from_parquet`:
```python
    # Percorsi dei binari memmap (priorità a dataset allegati a zero-startup)
    dat_user, dat_agent, dat_codes = _find_dat_files(parquet_path)
    if dat_user is not None:
        _shp_user = (os.path.getsize(dat_user) // (MEL_BINS * 2), MEL_BINS)
        _shp_agent = (os.path.getsize(dat_agent) // (MEL_BINS * 2), MEL_BINS)
        _n_cb = int(
            np.fromfile(dat_codes, dtype=np.int16, count=1)[0]
            if os.path.getsize(dat_codes) >= 2
            else N_CODEBOOKS
        )
        _n_frame = (os.path.getsize(dat_codes) - 2) // (2 * _n_cb)
        user_mel = np.memmap(dat_user, dtype=np.float16, mode="r", shape=_shp_user)
        agent_mel = np.memmap(dat_agent, dtype=np.float16, mode="r", shape=_shp_agent)
        _codes_flat = np.memmap(dat_codes, dtype=np.int16, mode="r")
        agent_codes = _codes_flat[1 : 1 + _n_cb * _n_frame].reshape(_n_cb, _n_frame)
        t_el = time.time() - t0
        print(f"[Fase 2 - DataLoad] MEMORY-MAPPED da {os.path.dirname(dat_user)}: {agent_codes.shape[1]} frame in {t_el:.3f}s (0 copie RAM).", flush=True)
```

In questo modo, allegando il dataset coi `.dat`, la chiamata `KP.convert_parquet_to_memmap(...)` ritorna immediatamente `True` in $0.001\text{s}$ senza toccare la memoria né allocare 3.3GB di RAM.
