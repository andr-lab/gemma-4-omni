## OBIETTIVO — PREP v3: tokenizza CV26 it in codici RVQ Qwen3-TTS + mel numpy

Ripeti per il dataset CV26 it il flusso di tokenizzazione già collaudato per MDC v2
(guarda lo script prep MDC v2 esistente e la cella prep di kaggle_pipeline.py — usa
la STESSA pipeline, NON reinventare):

1. **Lettura e filtraggio**:
   - Carica train.tsv (+ eventualmente validated che non sia in train). Filtra per:
     - `up_votes - down_votes >= 2` (clip validate)
     - durata clip ragionevole: 1.0s ≤ durata ≤ 15s (usa `clip_durations.tsv` se serve, o misura con soundfile)
     - testo non vuoto, solo caratteri validi (filtra righe con caratteri strani)
   - Obiettivo: **≥ 50 ore di parlato attivo** se possibile (CV26 it ha ~280k clip; anche al 60% di filtraggio siamo ampiamente sopra). Se il volume è enorme, valuta un campionamento stratificato per parlante (es. max N clip per client_id) per diversità, ma NON ridurre sotto le ~30h.
2. **Tokenizzazione RVQ (Qwen3-TTS Tokenizer 12Hz, 16 codebook)**:
   - Usa IL DECODER/ENCODER UFFICIALE: `Qwen3TTSTokenizerV2Model` (qwen-tts 0.1.1, venv phase1 `/opt/venv_phase1/bin/python`) — STESSO ambiente verificato nel Task 11E (il worker subprocess funziona).
   - Output per clip: `codes` (T_frames x 16, int), mel numpy (bit-pari col Gemma4AudioFeatureExtractor), durata.
   - Salva parquet con colonne come il prep v2 (verifica lo schema esistente: `data/train_tokens_mdc_v2_15.0h_11599s_codes.parquet` + file mel).
   - Nome output: `train_tokens_cv26_it_XX.Xh_NNNNNs_codes.parquet`
3. **Controlli anti-artefatto OBBLIGATORI (lezione dai 3 artefatti passati)**:
   - `CONSTANT_MEL_RATIO`: percentuale di clip con mel quasi costante — deve essere < 2% (il v2 degenerato era 44.66%, il v2 buono 0.96%)
   - distribuzione target: N valori distinti in CB0 per finestra campione (minimo ~20-30 diversi)
   - decodifica di 8 clip tokenizzate con decoder ufficiale → wav in `samples_cv26/` → verifica: corr@12.5Hz in [-0.1, +0.1], sub<100Hz < 2%, peak/rms 3-10
4. **Smoke**: prepara il training con 2-4 batch (PHASE2_SMOKE_BATCHES) e verifica che loss iniziale sia ~13-17 (NON ~0.002) prima di qualsiasi run completo.
